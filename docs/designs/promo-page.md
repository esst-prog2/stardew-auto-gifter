## Problem Statement

The mod works and is tested, but there is nothing a Stardew Valley player can land on, understand in a few seconds, and install from. The user wants the content of a promo page for the mod, aimed at Stardew players who would otherwise find it on Nexus, hosted on GitHub Pages.

## What Makes This Cool

The main feature is something that does not happen: you never press a button. You walk past Haley and she already has her Coconut ("Gave Coconut to Haley."). A still screenshot cannot show an absence, so the page has to open with motion: a short clip of the player walking through town while the gift messages appear. The second hook is trust. A mod that takes items from your chests by itself is scary, so "your rare items stay safe" comes right after the hero, not at the bottom.

## Constraints

- Audience: Stardew Valley players (Nexus-style), not the course. The course gets one short footer section.
- Hosting: GitHub Pages. The repository is public (the unauthenticated GitHub API returns 200 for it).
- No GitHub Release or tag exists yet, so there is nothing to download today.
- No in-game screenshots or clips exist yet; they are planned for December.
- Project rule: everything committed is in English.

## Premises

All five were accepted by the user (D4).
1. The page is in English.
2. The page states only what the code or an in-game test supports (claims about other mods: a cited external source, re-checked before publishing). Examples that depend on the game's gift-taste data (Haley -> Coconut, Abigail and the Prismatic Shard) are checked in-game in December. The page does not claim to be the only gifting mod.
3. A page without a download is an empty promise. A v0.1.0 GitHub Release (zip) is needed as a separate step. Until it exists, the download button says so honestly.
4. The hero is a moving clip of the no-button walk. Until December it is a labelled placeholder, never an invented image.
5. This session designs the content (sections and copy). It does not build the HTML.

## Approaches Considered

- **A: Minimal one-pager.** Rejected: too thin to build trust (no blocklist, no "one always stays").
- **B: Story-driven page.** Chosen.
- **C: Interactive Plan tab in JavaScript.** Rejected: the selection rule would be maintained twice (C# and JS) and could drift from the mod.

## Recommended Approach

Approach B, a story-driven page in seven sections, in this order: hero, how a day works, rare items stay safe, how it compares, install and first day, known limits, how it's built. The order follows the questions a player asks: what does it do, how do I use it, is it safe, how do I install it, what doesn't it do.

### Page copy, section by section

Every claim below lists its source. Quoted in-game texts match the code word for word.

**1. Hero**

- Headline: **Walk past. They get their gift.**
- Subline: Auto-Gifter is a SMAPI mod for Stardew Valley. In the evening you see tomorrow's gift plan; the next day, when you walk past a villager on the plan, the mod gives them their gift from your chests. No button to press.
- Media: `[Clip, recorded in December: the player walks through Pelican Town without pressing anything; "Gave Coconut to Haley." appears as they pass.]`
- Buttons: **Download v0.1.0** (links to the GitHub Release; until it exists: "Download coming soon", disabled) · **Source on GitHub**
- Small print: Stardew Valley 1.6.14+ · SMAPI 4.5+ · Single player
- Sources: `manifest.json` (`MinimumGameVersion` 1.6.14, `MinimumApiVersion` 4.5.0); `ProximityDeliveryService.cs:162` (message text); README section 3 (multiplayer is out of scope).

**2. How a day works** (heading: *Plan tonight. Sleep. Just walk tomorrow.*)

1. **Evening: press F8.** On the NPCs tab, tick the villagers you want to gift. The Plan tab shows tomorrow's gift for each of them, for example "[x] Haley -> Coconut".
2. **Change your mind.** Click a row to "[ ]" to leave that villager out tomorrow, for example when you want to give them something yourself.
3. **Next day: just walk.** Come within 1.5 tiles of a villager on the plan. One item leaves your chests, and a message says "Gave Coconut to Haley."

Note under the steps: *Plans always start the next day. Ticking a villager does not change today.*

How it picks (short paragraph): For each villager, Auto-Gifter first looks only in your marked chest: it picks the loved item you have the most of there (at least two), or, if there is none, a liked item (you can turn liked items off). Only if the marked chest has nothing for that villager does it look the same way through all the chests on your farm and in its buildings (barn, coop, shed, greenhouse). You can also tell it to use the marked chest only.

- Source for the order: `Planning/PlanComputer.cs:57-62` (anchor-only pool first, farm-wide pool only when that finds nothing and the "anchor chest only" setting is off).

- Sources: `ModConfig.cs` (`MenuKey` F8, `ChestMarkKey` G, `IncludeLikedItems` true); `ModMainMenu.cs:291-292` (row format); `ProximityDeliveryService.cs:22` (1.5 tiles); specs/gift-selection "Tiered, quantity-based item selection", "Anchor chest prioritized before the wider farm pool", "Farm-wide item pool"; specs/gift-selection "Starter chest and welcome message" (gifting starts the next day).

**3. Your rare items stay safe** (heading: *It never takes what you want to keep.*)

- **Blocklist.** Tick an item on the Blocklist tab, such as a Prismatic Shard, and it is left out of every plan worked out after that. Tomorrow's plan is worked out when you open F8, so after changing the Blocklist, close F8 and open it again to update tomorrow's plan. A gift already planned for today is not affected.
- **One always stays.** An item is only given if you have at least two of it, so you never lose your last one.
- **The game's limits, respected.** At most one gift per villager per day and two per week, checked again right before the hand-off.
- **An off switch.** The mod only works while exactly one chest is marked. Open a chest on your farm and press G to mark it; it is renamed "Auto-Gifter Chest". Press G again to unmark it, and gifting stops.
- **Villagers you have not met are skipped.** Their row says "Emily: not met yet - talk to them first".
- **It tells you when it can't.** If the mod has nothing it can give a villager today, or they already got two gifts this week, they tell you so when you walk up, once a day.
- **Only farm chests.** Chests in the farmhouse and its cellar are never touched.
- Sources: blocklist applied only when a plan is computed (`Planning/PlanComputer.cs`); tomorrow's plan is computed when F8 opens (`ModEntry.cs:218`) and at day end only if there is no active plan for tomorrow (`Core/PlanTiming.cs:22-23`, `ModEntry.cs:136-138`); ticking a Blocklist row only toggles the stored list (`ModMainMenu.cs:495`); no blocklist check at delivery (`Core/DeliveryRule.cs`, `Delivery/` have no blocklist check); `StockRule.MinimumUnitsForGift` = 2; `GiftLimitPolicy.WeeklyFriendshipGiftCap` = 2 and specs/proximity-delivery "Gift-limit re-checked at delivery time"; specs/gift-selection "Marked chest acts as the mod's on/off anchor", "Chest marked via a dedicated keybind…", `FarmChestScanner.cs:94` (chest name); `PlanRowText.cs:14`; specs/proximity-delivery "In-person notice when nothing is available"; specs/gift-selection "Farm-wide item pool".

**4. How it compares**

Prose, no table, no named competitors: *Other gifting mods exist. Some send gifts from a chest when you press a key; others remind you who to gift. Auto-Gifter does not need a key press, and it picks the item for you: the one you have the most of.*

- Source: an external, cited source (see Success Criteria): Nexus Mods pages https://www.nexusmods.com/stardewvalley/mods/20838 (sends gifts from an opened chest on Shift+G) and https://www.nexusmods.com/stardewvalley/mods/26008 (gifting reminders), found by web search on 2026-11-12. Re-check both pages before publishing. The page does not name them.

**5. Install and first day**

1. Install [SMAPI](https://smapi.io).
2. Download the zip from the Releases page and unzip it into your game's `Mods` folder. (Until the v0.1.0 Release exists, this step reads "Download coming soon", the same as the hero button.)
3. Start the game and load your save. The first time you step out onto your farm, you get a chest and a short welcome message.
4. Place the chest outside on your farm, or in a barn, coop, shed or greenhouse (not in the farmhouse). Open it and press G. The chest is renamed "Auto-Gifter Chest": that means it is marked.
5. Press F8 and tick the villagers you want to gift. Gifting starts the next day.

Settings: the keys and the liked-item fallback are in `config.json` (`MenuKey`, `ChestMarkKey`, `IncludeLikedItems`). The Settings tab of the F8 menu has "Only use the marked chest (ignore other farm chests)".

- Sources: `ModConfig.cs`; `ModMainMenu.cs:328` (setting label); specs/gift-selection "Chest marked via a dedicated keybind while its inventory is open" (farm chests only) and "Farm-wide item pool" (farmhouse excluded); `FarmChestScanner.cs:94`; specs/gift-selection "Starter chest and welcome message on first farm exit"; specs/daily-plan-review "Anchor-chest-only setting in the mod menu".

**6. Known limits**

- Single player only; not tested in multiplayer.
- F8 does nothing while a chest or another menu is open. Close it first.
- Changes always apply from the next day. After changing the Blocklist, reopen F8 so tomorrow's plan is worked out again.
- This is version 0.1.0, an early release.
- Sources: README section 3 ("Not this term"); `ModEntry.OpenModMenu` guard (`Game1.activeClickableMenu != null`); `manifest.json` version.

**7. How it's built** (footer)

Built as a programming course project: a C# SMAPI mod, developed spec-first with OpenSpec, with 101 unit tests for the selection and delivery rules. The specs, the planning log and the reviews are in the repository.

- Sources: `openspec/`; `dotnet test` result 101/101 on 2026-11-07; `PLANNING_LOG.md`, `reviews/`.

## Open Questions

- **December media:** the hero clip and the three step screenshots do not exist yet. The page ships with labelled placeholders until then.
- **Gift-taste examples:** "Haley -> Coconut" is used as an example. It comes from the game's data, not the code; check it in-game with the December screenshots (already planned in `update-demo-description` task 3.1).
- **GitHub Pages access:** the repository belongs to the `esst-prog2` organization. Enabling Pages needs admin rights on the repo; check whether the user has them or the course staff must enable it.
- **Blocklist timing (a mod gap, not a page question):** the blocklist only takes effect when a plan is next computed. Ticking an item does not update the plan already open in F8, and the mod does not re-check the blocklist when it hands a gift over. So an item blocklisted today can still be given today (today's plan) and tomorrow (if tomorrow's plan was computed before the tick and F8 is not reopened). The page says this plainly. Whether to recompute tomorrow's plan when the blocklist changes, or to re-check the blocklist at delivery, is a separate change and the user's decision.
- **Release zip:** check whether the build's mod zip (from `Pathoschild.Stardew.ModBuildConfig`) is the right Release asset, and whether it contains only the mod files.
